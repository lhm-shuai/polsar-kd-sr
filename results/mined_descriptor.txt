Low-complexity descriptor (the paper's general-purpose operator, Eq. (16))
--------------------------------------------------------------------------
    Pmv = exp( -c / (Pm + Pv) ),   c = 0.20430441

    c is the mean of the five official seeds (42, 123, 211, 666, 789):
        42 -> 0.21386275   123 -> 0.21064375   211 -> 0.21132621
        666 -> 0.20430441  789 -> 0.20927252
        mean = 0.20988, maximum relative deviation 2.66%

    Node complexity 6; three floating-point operations per pixel.

    Note: exp(-c/x) is strictly monotone in x = Pm + Pv, so this descriptor
    has exactly the same AUC and essentially the same accuracy as the raw sum
    Pm + Pv. Its value is that it is closed form, costs three operations, and
    maps to (0, 1) with the saturation behaviour of a membership probability
    - not that it ranks better. scripts/04_evaluate.py prints both so the
    comparison is always visible.


High-complexity descriptor (the paper's Psmv, Eq. (24), Table IV / Table IX)
--------------------------------------------------------------------------
    Psmv = C29, the deep-end point of the seed-666 Pareto front:

        A = exp( Pv * (-0.72197366 - Ps) ) / ( Pm^2 + 1.0250757 )
        t = cos( A^8 + 0.48293668 )
        t = sin(t) / 0.61469054
        t = sin( sin(t) )
        t = t^2 / 0.49011374
        Psmv = sin(t)^8

    This is the canonical Psmv used by the paper: Eq. (24), the last row of
    Table III, and the Pmvs detector input.

    The archived Table IV/IX scores (AUC 0.9867 on the PSDD 1:2 balanced
    sample set) were produced by the numerically equivalent three-sine
    transcription of the same C29 point, implemented as `psmv_archived` in
    `src/evaluate.py`; the archived transfer scores use the same transcription.
    The two transcriptions share the same constants and differ by <= 3e-4 in
    AUC (0.9867 vs 0.9864); they are the same descriptor, not two different
    ones.


Historical transcriptions (kept for replay, NOT the paper's Psmv)
------------------------------------------------------------------
    C13: cos( ( exp( (-0.6271455 - Ps) * Pv ) / ( Pm^2 + 0.7921049 ) )^2 )
         An intermediate-revision expression.  It is not Psmv.

    C16: sin( cos^2( E^4 ) ),
         E = exp( (-0.69994015 - Ps) * Pv ) / ( Pm^2 + 0.87565625 )
         The legacy `final_tables.py::psmv` implementation used to reproduce
         the old Table V row in the v90 pipeline.  It is not the paper's
         Eq. (24) and should not be used as the canonical Psmv.

    When in doubt, use `src/evaluate.py::psmv` (C29) and
    `src/evaluate.py::psmv_archived` (the three-sine transcription of C29).
