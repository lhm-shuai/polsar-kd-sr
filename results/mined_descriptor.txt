Low-complexity descriptor (the paper's general-purpose operator)
----------------------------------------------------------------
    Pmv = exp( -c / (Pm + Pv) ),   c = 0.20430441

    c = 0.20430441 is the seed-666 constant used to render the P_mv images
    fed to the detectors.  The five converged seeds of the paper's Table III
    give:
        42 -> 0.214   123 -> 0.210   211 -> 0.211   666 -> 0.204   789 -> 0.209
        mean = 0.2098, maximum relative deviation 2.7%.

    Because Pmv is strictly monotone in (Pm+Pv), c changes the operating point
    but not any ranking, accuracy or AUC.  The paper therefore also reports the
    raw sum Pm+Pv; on the 1:2 balanced test sample both have AUC 0.9772.

    Node complexity 6; three floating-point operations per pixel.

Note on what this is worth
--------------------------
exp(-c/x) is strictly monotone in x = Pm + Pv, so this descriptor has exactly
the same AUC and essentially the same accuracy as the raw sum Pm + Pv.  Its
value is that it is closed form, costs three operations, and maps to (0, 1)
with the saturation behaviour of a membership probability - not that it ranks
better.  scripts/04_evaluate.py prints both so the comparison is always visible.


High-complexity descriptor (paper Table IV row "Psmv (C=13, ref.)")
--------------------------------------------------------------------
    Psmv = cos(A^2),   A = exp( (-0.6271455 - Ps) * Pv ) / ( Pm^2 + 0.7921049 )

    Complexity-13 point of the seed-666 Pareto front.  It is the expression
    behind the paper's Table IV row "Psmv (C=13, ref.)" (accuracy 95.34%,
    AUC 0.9867).  It is reported only as a pixel-level reference; it is NOT
    used in the detector experiments.

    The paper's earlier C=29 transcription is retained below only so that
    older logs can be replayed exactly.
